# Growth Roadmap — Theme Studio + AI-Native (Moat-First)

> Status: Implemented (Phase 6–7 planned slices, 2026-07-31)
> Approach: Theme Studio (interactive authoring, engine as internal module)
> Capacity: Solo maintainer, part-time — thin slices, zero operational burden

---

## Understanding summary

- Long-term growth roadmap built on two moat anchors: (1) evolve the theme system into a design platform — Theme Studio authoring, token export, Figma kit — and (2) AI-native depth — machine-readable component metadata and a registry MCP server.
- Moat-first strategy: every addition must make Hewn harder to clone. Defensibility over component count, revenue, or feature parity.
- Sequence: Phase 5 (distribution) → Phase 6 theme platform → Phase 7 AI-native — planned slices for all three are shipped. Remaining items are deferred non-goals (payments, hosted AI, context packs, Playwright e2e).
- New components are added only where they demonstrate the moat (theme + motion + glass together) — charts/data-viz is the signature family.
- Solo part-time: every slice independently shippable; no servers, no accounts, no hosted AI; everything generated from canonical sources.
- AI theme generation is BYOK client-side; AI proposes, the validation engine disposes — nothing AI-generated bypasses guardrails.

## Assumptions

1. Phase 5 completes before Phase 6 begins (npm subpaths, CLI detection, registry generation, static free registry, Pro stubs).
2. Strict anchor sequencing; only cheap groundwork (llms.txt via docs-metadata) overlaps Phase 6.
3. Theme authoring runs client-side in `apps/web`; export is file-download; no backend. Existing bundle budgets apply.
4. Static deploys only; registry stays static JSON; MCP ships as a local npm package (stdio), not a hosted service.
5. No accounts, no telemetry, no user data; MCP is read-only.
6. CI generation gates keep failing builds on missing metadata; visual snapshot matrix extends to authored themes.
7. All artifacts generated from canonical source; no hand-maintained parallels.
8. Figma deliverable is a generated community kit + Tokens Studio JSON, not a Figma plugin.
9. Pro features are marked/gated via registry tier + docs + CLI stubs now; payment enforcement lands with monetization.
10. Success criteria: (a) user authors a custom theme in Studio and exports working tokens without writing CSS; (b) AI coding tools consume Hewn metadata/registry to scaffold on-brand UI; (c) every slice ships with docs, tests, npm + CLI install paths.

## Final design

### Architecture (three layers, no new packages, no backend)

1. **Authoring engine** — `packages/themes/src/authoring/`. Pure functions: token schema (TS types mirroring pack CSS), base-pack derivation (`pack + override map → resolved tokens`), OKLCH scale helpers, validation (contrast floors, unsupported-mode guards), exporters (CSS, Tailwind v4 `@theme`, Style Dictionary JSON, Figma variables JSON). Consumed by apps/web today; CLI/MCP later.
2. **Studio surface** — `/docs/theme-studio`, reusing docs shell + Theme Lab preview machinery. Controls left, live preview (shell + component matrix) right. State = `basePackId + overrideMap`; applied via the same `data-theme` CSS-variable mechanism as packs.
3. **Tier boundary** — Free: base pack + accent seed, radius presets, CSS export. Pro (stub-gated): full token editing, all export formats, Figma variables JSON.

Persistence: localStorage + import/export of override map JSON with `schemaVersion` migrations.

### Authoring model

Six token groups: accent (free), neutrals/surfaces (Pro), semantic colors (Pro), shape/density (Pro; free keeps radius presets), glass (Pro), motion character (Pro).
Guardrails: WCAG AA contrast floors at derivation time (advisory AAA); light/dark derived as a pair; authored themes declare supported modes like curated packs.
Exclusions: no free-form CSS, no custom fonts (OFL stack is brand), no arbitrary new tokens.
Output is a **custom pack** identical in shape to curated packs.

### Export pipeline + Figma

| Format | Tier | Story |
|--------|------|-------|
| Pack CSS | Free | Drop-in `[data-theme]` file; stands alone without Hewn installed (adoption wedge) |
| Tailwind v4 `@theme` | Pro | CSS-first config block |
| Style Dictionary JSON | Pro | Multi-platform token pipelines |
| Figma variables JSON | Pro | Tokens Studio–compatible |

Figma kit: generated community file (variables/styles for six packs + core sticker sheet: Button, inputs, surfaces). Full component parity is future scope.
CLI hook (`hewn theme export`) is groundwork-only — thin wrapper over engine later.

### Charts (signature family)

d3 primitives (`d3-scale`, `d3-shape`, `d3-array`) + `motion/react`; Hewn owns rendering/styling/a11y (first non–React Aria behavior family: `role="img"` + summary, optional visually-hidden data table).
First set: Sparkline, LineChart, AreaChart, BarChart. Donut/radial later.
Series colors from accent ramp + semantic hues; grid/axis from neutral tokens; `tabular-nums`; draw-in on mount, spring on data change, static under reduced motion.
Concise props for simple use; compound `Chart.Tooltip`/crosshair for line/area. Own npm subpath + registry entries. Standard loading/empty/error states.

### Phase 7 — AI-native

1. **Canonical AI schema** — docs-metadata deepened into versioned machine-readable per-component schema (props/types, compound parts, states/variants, keyboard contract, tokens consumed, install commands, examples). CI-fails when incomplete.
2. **llms.txt** — generated; cheap enough to land as Phase 6 groundwork.
3. **`@hewnui/mcp`** — stdio, read-only. Tools: `list_components`, `search_components`, `get_component`, `get_install_command`, `get_theme`, `get_tokens`. Pro items fail closed until licensing.
4. **AI-Pro (in scope)**: Pro components/blocks via MCP (license-key gated with payments); AI theme generation/migration in Studio (prompt / existing Tailwind-CSS / logo → valid pack), BYOK client-side.

### Error handling

- Unreachable contrast: engine clamps to nearest valid ramp and reports the adjustment.
- Corrupt/old override JSON: migrate via `schemaVersion`; unrecoverable → clear error, state untouched.
- Pack-id collisions: validated, kebab-cased, uniquified.
- Existing rules extend to authored packs: reduced-motion override, glass opaque fallback, invalid theme → Forest Light.
- BYOK missing/invalid → manual authoring fallback; generation is an accelerator, never a dependency.
- Charts: SSR-safe; animation failure → static render; d3 failure isolates to chart subpath.
- MCP: read-only by construction; registry unavailable/corrupt → structured errors.

### Testing

- Vitest: engine (derivation, ramps, contrast, exporters, migrations) — highest-value surface.
- RTL + axe: Studio controls, chart states/a11y.
- Visual snapshots: authored-theme matrix joins curated matrix.
- Playwright: author→export, import→migration flows.
- Build tests: exports compile (CSS parses, `@theme` loads, JSON validates).
- MCP: contract tests against fixtures; schema validation in CI.

### Slice plan

**Phase 6**: 6.1 engine core (M) → 6.2 Studio MVP free tier (L, minimum viable moat) → 6.3 Pro authoring groups (L) → 6.4 Pro exporters (M) → 6.5 Figma kit (M) → 6.6 charts (L, splittable) → 6.7 llms.txt (S, anywhere after 6.2).
**Phase 7**: 7.1 AI schema v1 (M) → 7.2 `@hewnui/mcp` (M) → 7.3 Pro-via-MCP plumbing (S) → 7.4 AI theme generation/migration (M).
No slice depends on a later one; each ships with docs/tests per release gates.

## Non-goals

- Auth, payments, license validation (deferred)
- Hosted AI services, per-request inference (until revenue funds it)
- Visual page builder, hosted theme service, accounts
- Component-parity additions
- Context packs, team registries, community theme sharing, Figma full parity, donut charts — all future scope
